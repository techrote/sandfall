### Frozen Current semantic classes

The reconciliation preserves four classes: compact pair-table reactions;
source-driven neighbourhood/context mechanisms; intrinsic/lifecycle transitions;
and kinetic/contact systems that affect contact opportunity but are not INT-owned.

Representative specialized authority was re-located on current world.cpp: Steam,
Fire/Combustible, Gunpowder/Coal, Metal, Cement, MoltenGlass, Lava/Ice, Acid,
Cloner, Plant/Fungus/Seed, Mite, Rocket and Foam. Their non-kinetic semantics are
represented by stable IDs in the new profile while their current world.cpp
execution remains authoritative at this checkpoint.

### Non-authoritative schema/model

native/include/cybersand/interaction_rules.hpp establishes schema/profile/tuning
pass identity, seven stable channels, 14 sparse compact rules with stable IDs,
role-preserving participant semantics, explicit semantic-family membership,
specialized Current provenance, authored/evidence coverage statuses, accounting
notes, targeted revalidation tags and a constexpr sparse pair resolver.

No production callsite uses the new resolver yet at this checkpoint.

### Frozen-oracle/shadow proof

native/tests/test_world.cpp adds an exhaustive shadow comparison. For every pair
of current material IDs and representative probability boundaries, the new
resolver is compared against the existing MaterialRules::pair_reaction oracle.
Selected outcomes and role-specific products must match exactly.

The same test protects exact rule inventory, stable channel/schema/profile
identity, reverse-role Acid/Metal effects, Water+Sand non-interaction, explicit
base-Metal/base-Glass family membership, themed non-inheritance and coverage/pass
metadata.

This checkpoint intentionally stops before production authority changes. Runtime
execution is not yet claimed; exact-head CI evidence is recorded after publication.

## Implementation after the pre-authority checkpoint

### Layered schema/compiler and stable identities

The permanent source of truth is
`native/include/cybersand/interaction_rules.hpp`. It now defines:

- schema `cybersand.interactions/v1`, Current profile
  `int.current-behaviour/v1` and root pass
  `int.pass.current-oracle/v1`;
- seven independent channels;
- explicit semantic families/memberships, never inferred from material names;
- five deterministic layer classes with precedence
  channel default < family default < material adjustment < pair override <
  context modifier;
- zero implicit Current layer defaults/adjustments/modifiers, so the
  infrastructure does not fabricate new Current semantics;
- stable version/supersession/pass IDs, accounting notes and subsystem
  revalidation tags;
- catalogue validation for duplicate/overlapping rule identities, invalid family
  references, equal-precedence layer conflicts and invalid self-supersession.

Synthetic native regressions prove family/material/context precedence and explicit
conflict reporting. Ordered, symmetric and unordered-role-preserving pair domains
are separately testable; opposite ordered directions are legal while genuinely
overlapping ordered/unordered domains are rejected.

### Compact Current authority migration

The 14-entry pre-migration pair table is preserved literally inside
`native/tests/test_world.cpp` as an independent oracle. Across all material IDs,
both orientations and representative probability boundaries, the versioned
resolver must match the frozen oracle's selection and role-specific products.

After that proof was published, the only production semantic migration in #29 was
bounded to `MaterialRules::has_pair_reactions` /
`MaterialRules::pair_reaction`: the public boundary now delegates to
`InteractionRules`. The four-tick contact lane, deterministic neighbour/random
inputs, Water initialization, writes, worker ownership and all movement remain
unchanged in `World`.

Nineteen representative source-driven/lifecycle mechanisms are assigned stable
provenance IDs but retain their existing `world.cpp` authority. This includes
Steam, Fire/Combustible, Gunpowder/Coal, Spark/Metal, Cement, MoltenGlass,
Lava/Ice, Acid, Cloner, Plant/Fungus/Seed, Mite, Rocket and Foam. No architectural
rewrite was performed merely for uniformity.

### Provenance, coverage and rolling revalidation identity

`CyberDemoBridge.inspect_interaction_profile()` exposes copied
schema/profile/channel/layer/family/rule/coverage/pass data and catalogue
validation. `inspect_interaction()` exposes all seven per-pair channels, compact
rule direction/selection/products, authored-layer match/conflict/effective origin,
specialized source/target mechanism provenance, selected-pass
parent/disposition/change declaration and revalidation tags. These methods are
read-only serialized-owner inspection, not a second authority.

The coverage ledger separates authored status from evidence status and explicitly
retains untested gaps. The themed-metal record was narrowed during final review:
themed metals do not inherit the base Acid+Metal Smoke/Rust compact pair override,
but the existing broad Acid neighbourhood corrosion kernel still applies.

Schema-2 summaries/captures also retain a `kinetic_contact_baseline` containing
source/runtime identity, transport hash, Water semantics/effective policy,
execution/interest settings and worker count. That identity is for targeted
re-screening only; INT-000 does not own the kinetic systems it records.

### Generated fixtures, Materials Laboratory and batch evidence

The proof set is generated through the existing schema-2 catalogue/host, with no
scenario-specific physics:

- Water+Salt;
- Water+Sand non-interaction control;
- Lava+Water;
- Fire+Gunpowder;
- Acid+Metal;
- Spark+Metal;
- Cement+Water/air-context cure.

The same complete definitions are accepted by Materials Laboratory, canonical JSON
export and the native-only runner. Mechanism fixtures now have bounded effect
conditions rather than horizon-only success: Gunpowder must be consumed, Rust must
be produced, an adjacent Spark population must be consumed by the Metal fixture,
and Concrete must be produced. The existing Salt/Brine and quench observations
retain exact species/product counts and the scheduled Water ledger never fabricates
reaction source/sink accounting.

`test_microscenarios.gd` covers profile/provenance, selected-pass data,
per-channel origin/conflict, rolling baseline identity, deterministic repeat and
one/four-worker semantic parity. `test_microscenario_materials_lab.gd` covers
same-definition canonical JSON, all Play/Inspect/Benchmark modes, observer on/off,
one/four workers, exact Salt/Brine/Water accounting, all Lab presets and
transactional invalid replacement.

`tools/interactions/batch.py` delegates execution to the same schema-2 runner.
It fails on worker-semantic drift, retains the complete interaction catalogue and
rolling contact baseline, emits coverage summaries/gaps, and compares two retained
manifests by stable rule/layer/pass identity down to changed fields. Input
manifests are never overwritten; comparison differences are evidence for review,
not automatic tuning decisions.

### Scope and platform limits

INT-000 selects no broad material tuning. It does not change Water transport/head,
density exchange, granular support/bridging, erosion/entrainment,
collision/ballistics, Rapier, soliding or scheduler ownership. Deep specialized
mechanisms remain in current kernels where exact extraction is not useful.

Actual Windows execution, browser/WebAssembly execution and target-GPU performance
are not #29 infrastructure acceptance claims unless a later dated run records
them. A Windows x86_64 cross-build is build/ABI evidence only.
